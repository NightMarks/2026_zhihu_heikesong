# 沙游心语「选择镜像」玩法设计

**日期：** 2026-09-15  
**状态：** 已完成产品讨论，等待用户审阅  
**适用版本：** 知乎黑客松 MVP

## 1. 背景

现有产品已经形成“知乎内容探索 → 获取灵感值 → 解锁沙具 → 自由创作 → AI 报告 → 社区互动”的完整流程，但主要反馈集中在创作完成之后。玩家在创作过程中缺少明确情境、连续决策和可回看的变化，因此功能完整但重复游玩的动机较弱，心理分析也容易成为与游戏分离的结算页。

本设计新增「选择镜像」玩法：系统通过连续的沙盘情境，让玩家直接以增删、移动和重组沙具的方式作答；系统比较玩家在不同情境中的实际操作，帮助其认识反复出现的选择方式。玩法不判断选择对错，不把单个沙具解释为人格，也不进行心理诊断。

「选择镜像」不会替换现有自由创作流程。主页在现有「沙盘报告」旁增加「每日热题」入口，两种模式共用知乎登录、沙具库、沙盘编辑器、AI 分析、作品发布、社区互动和好友关系。

## 2. 产品目标

### 2.1 核心目标

- 把心理探索变成玩家的主要操作，而不是完成沙盘后的附加报告。
- 让一局游戏包含情境、选择、变化、对照和自我确认，形成可重复体验。
- 通过跨局记录帮助玩家认识“我通常怎样作出选择”，而非告诉玩家“我是什么人”。
- 利用知乎热榜生成每日新鲜命题，同时保持内容安全和输出稳定。
- 用可变化的「选择原型」提供收集感、传播性和长期回访动力。
- 让每日热题作品无缝进入现有发布与好友匹配流程，而不是形成隔离的第二套社区。
- 允许玩家自主决定公开哪些选择原型，以及是否使用公开原型参与好友匹配。

### 2.2 成功标准

- 新玩家能在 6—8 分钟完成一局，不需要理解心理学术语。
- 玩家能在结算时指出至少一条由自己操作支持的选择模式。
- 每条心理联想均能回溯到具体沙盘变化，并允许玩家确认、否认或改写。
- 热榜或 AI 不可用时仍可完成整局。
- 三分钟演示能够清楚展示“同类情境下的两次选择对照”。

### 2.3 非目标

- 不诊断心理疾病，不推断固定人格、依恋类型或健康程度。
- 不对玩家选择进行好坏评分，不设置心理健康排行榜。
- 不在 MVP 中实现实时双人协作、无限 AI 题库或复杂成就系统。
- 不公开完整选择图谱、未经确认的 AI 推测或私人自述。

## 3. 设计原则

1. **行为先于解释：** 先记录玩家做了什么，再讨论其可能含义。
2. **变化先于成品：** 制作和调整过程比最终构图更重要。
3. **用户拥有解释权：** 未经玩家确认的联想不进入长期图谱。
4. **对照而非判定：** 通过相似情境的不同版本发现重复与变化，不设置标准答案。
5. **原型可以变化：** 选择原型只概括近期被确认的行为，不定义玩家。
6. **热点只提供议题：** 知乎热点被抽象为变化、关系、取舍等主题，不消费现实人物的困境。

产品核心表达：

> 我们不根据你选了什么来定义你，而是陪你看见，你总是怎样作出选择。

## 4. 单局核心流程

一局目标时长为 6—8 分钟，由五个阶段组成。

### 4.1 选择今日挑战

主页主导航在「沙盘报告」旁展示「每日热题」。该入口使用独立的挑战状态，不改变「我的沙盘 → 沙盘报告」原有自由创作路径。

进入每日热题后展示：

- 今日命题名称与一句引导语；
- 抽象后的知乎话题来源；
- 预计用时；
- 本局主要观察维度；
- 「开始照见我的选择」按钮；
- 跳过当前题目并使用内置题目的入口。

MVP 的内置保底命题为《为未知留一个位置》，主要观察“面对变化”，辅助观察边界与关系调节。

### 4.2 建立初始世界

玩家从已解锁沙具中选择 6—10 件，沿用现有沙盘编辑器完成初始布局。提交前填写一句可选自述，说明作品中最重要的元素或关系。

提交后保存不可变的初始快照。后续允许回看，但不能覆盖该快照。AI 此时只能复述可观察事实并确认玩家自述，不做模式判断。

### 4.3 完成三轮镜像试炼

MVP 固定覆盖三个情境维度：

1. **变化：** 一个陌生元素将进入沙盘，玩家用有限操作表现希望它如何进入。
2. **取舍：** 系统要求移除或失去部分元素，玩家决定保留什么并重新安排剩余世界。
3. **关系：** 一个孤立元素希望靠近另一个元素，玩家决定是否回应、由谁移动以及如何连接。

每轮由一张情境卡说明目标和限制。玩家不选择文字答案，而是在沙盘上直接操作。限制可以是最大移动次数、不可删除、必须保留某类元素等，但不设置胜负条件。

每轮保存开始快照、结束快照、操作序列和客观差异。玩家可跳过令其不适的情境，不损失已有进度。

### 4.4 平行世界重演

系统选择前述一个维度给出反向或变式情境，用于区分稳定选择与情境反应。例如：

- 原情境：陌生事物主动靠近玩家的世界；
- 变式情境：玩家需要主动接近未知区域。

两次情境使用相同的观察维度，但不强迫相同操作，也不将一致或变化解释为好坏。

### 4.5 生成选择镜鉴

结算页提供：

- 初始沙盘与最终沙盘对照；
- 三次关键变化的回放；
- 本局操作数据摘要；
- AI 生成的“事实 → 可能性 → 确认问题”；
- 「这很像我」「只在这个情境如此」「不符合我的想法」和自由改写；
- 经确认后生成的镜鉴卡。

结算后提供「发布这座挑战沙盘」和「寻找共鸣伙伴」入口。发布操作复用现有作品可见性、报告摘要、点赞、收藏、评论和好友申请能力；挑战来源、镜鉴卡和公开原型作为可选扩展字段保存。

示例：

> 事实：在陌生船靠近时，你先扩大围栏；主动探索时，你仍先移动树木形成缓冲。  
> 可能性：你也许习惯先确认安全条件再接触变化，也可能只是偏好层次清晰的构图。  
> 确认问题：哪一种更接近你当时的想法？

## 5. 心理观察模型

系统只记录中性、可观察的行为维度。

| 维度 | 可观察行为示例 |
|---|---|
| 边界方式 | 加强隔离、设置缓冲、开放通道、撤除边界 |
| 面对变化 | 接纳新元素、延迟处理、重新组织、移除变化源 |
| 关系调节 | 移动自己、移动他者、双方靠近、保持距离 |
| 资源取舍 | 优先保护、主动舍弃、平均分配、集中投入 |
| 控制策略 | 先规划后行动、边试边改、维持原状、彻底重构 |

### 5.1 三层解释结构

每条观察必须经过以下三层：

1. **事实层：** 描述具体、可验证的操作或布局变化。
2. **可能性层：** 最多提出两个替代解释，使用概率语言。
3. **确认层：** 玩家确认、限定、否认或自行改写解释。

只有玩家选择「这很像我」或提交自己的改写后，观察才可参与长期统计。「只在这个情境如此」保留在本局记录中但不作为跨局稳定证据；「不符合我的想法」用于抑制相同推测再次出现。

### 5.2 明确禁止的输出

- 根据单个沙具套用象征词典；
- 使用“你就是”“说明你患有”等确定性表述；
- 输出疾病、创伤、依恋或人格障碍诊断；
- 把不操作、跳过题目或中途退出解释为心理特征；
- 用其他玩家的选择作为健康、正常或优秀标准。

## 6. 每日命题与知乎热榜

### 6.1 生成流程

```text
知乎热榜
  → 内容风险过滤
  → 提取抽象心理主题
  → 匹配人工定义的挑战骨架
  → AI 填充情境文本
  → 结构和安全规则校验
  → 按北京时间日期缓存
  → 发布今日挑战
```

AI 不能直接把现实事件改写成心理题。服务端先把热榜条目归纳为“变化、关系、边界、资源、冲突、不确定性”等抽象主题，再选用经过审核的挑战骨架。AI 只负责生成温和、简洁、不指向具体当事人的情境文本。

### 6.2 内容过滤

包含下列主题的热榜条目不能进入命题生成：

- 自杀、自伤、死亡和重大灾难；
- 严重疾病和医疗求助；
- 未成年人受害；
- 性暴力、家庭暴力和其他现实暴力事件；
- 正在发生的公共安全事件；
- 对具体自然人的争议、指控或隐私内容。

若当天没有合适条目、知乎接口失败、AI 失败或校验不通过，服务端直接返回内置命题。相同日期默认返回同一个已缓存挑战，避免刷新后题目变化。

### 6.3 挑战结构

```json
{
  "id": "2026-09-15-change-01",
  "date": "2026-09-15",
  "title": "为未知留一个位置",
  "sourceTopic": "新事物进入日常生活",
  "primaryDimension": "change",
  "intro": "一个陌生元素即将进入你的世界。",
  "rounds": [
    {
      "id": "approach",
      "dimension": "change",
      "prompt": "请表现你希望它如何进入。",
      "constraints": { "maxMoves": 3 }
    }
  ],
  "fallback": false
}
```

服务端只接受白名单内的维度、轮次类型和限制条件。AI 不能生成可执行代码、HTML 或任意客户端行为。

## 7. 长期选择图谱

### 7.1 图谱内容

选择图谱默认私密，包含三个视图：

- **重复模式：** 哪些已确认选择在不同局中反复出现；
- **触发条件：** 模式主要出现于变化、关系、资源或边界等哪类情境；
- **可能变化：** 玩家在何时尝试过不同处理方式，以及其自述原因。

统计页面只显示事实次数、情境分布和玩家确认内容，不显示伪精确的心理百分比。

### 7.2 镜鉴卡

每局可生成一张镜鉴卡，由本局沙盘截图、关键变化、玩家确认的一句话和日期组成。示例名称包括：

- 《先留一条退路》
- 《由我先走过去》
- 《保护最重要的那个》
- 《重新摆一次也没关系》

卡名可以由规则库匹配，再由 AI 做语言润色。玩家可以收藏或主动分享到社区；默认不公开。

### 7.3 选择原型

原型是近期选择方式的游戏化概括，不是人格分类。候选原型包括：

- **边界守望者：** 多次先建立缓冲，再允许接触；
- **主动连接者：** 多次移动自我代表元素，主动发起关系变化；
- **秩序重构者：** 面对压力时多次重新安排整体结构；
- **核心守护者：** 资源受限时多次优先保护最重要元素。

生成条件：

- 最近 7 局中至少完成 3 局；
- 同一模式至少被玩家确认 3 次；
- 至少跨越 2 个不同情境；
- 没有被玩家明确否认的同类推测占主导。

原型由确定性规则计算，AI 只能润色说明。每张原型卡显示统计周期、支持证据和免责声明。新记录可以改变或移除原型；玩家可以隐藏、清除或拒绝生成。

每个原型具有独立的「公开展示」和「允许参与匹配」设置。「允许参与匹配」只能在已经公开时开启；关闭公开会同时关闭匹配。玩家可以只公开一个或多个自选原型，未公开原型对其他用户和社区接口不可见。公开页面需要同时展示“近期选择方式、可随新记录变化、不是人格诊断”的提示。

## 8. 社区辅助玩法

每日挑战允许玩家自愿发布沙盘和镜鉴卡。挑战作品沿用现有作品数据和互动流程，并增加挑战 ID、挑战标题、可选镜鉴卡及用户主动公开的选择原型。社区不比较心理健康程度，不展示原型排行榜。

同一命题完成后，可以展示匿名、聚合后的选择路径，例如“先调整边界”“先移动自我代表元素”“重组整体布局”。聚合统计必须达到最低样本量后才显示，防止识别单个玩家。

社区互动在现有点赞、收藏和评论之外，增加：

- 「我看见了另一种选择」；
- 「这个处理方式给了我启发」；
- 查看玩家主动公开的挑战作品；
- 在完成自己的挑战后回答“哪种处理方式是我没有想到的？”
- 查看作品作者主动公开的选择原型；
- 在发起匹配前勾选哪些自己的公开原型可以参与本次匹配。

完整选择图谱、未经确认的 AI 推测和私人自述不能随作品自动发布。

好友匹配保留现有沙具类别、具体沙具、空间布局、密度和报告关注方向，并新增一个默认关闭的「选择原型」匹配维度。发起方需要为本次匹配勾选自己的原型，候选方的原型还必须同时处于“公开展示”和“允许参与匹配”状态；只有满足这些条件的同名或相近原型可以参与计分。匹配结果必须分别说明“作品结构相似”和“公开原型相似”，不能把二者合并解释为心理适配度。用户可以完全关闭标签匹配，关闭后结果与现有匹配逻辑一致。

## 9. 系统结构

### 9.1 新增服务端模块

- `server/challenges.js`：获取热榜候选、过滤风险、匹配题目骨架、生成并缓存每日挑战。
- `server/challenge-schema.js`：挑战 JSON 的白名单校验与规范化。
- `server/choice-analysis.js`：校验轮次数据、组织 AI 输入、校验观察输出。
- `server/archetypes.js`：根据已确认观察计算选择原型。

### 9.2 新增前端模块

- `public/js/challenge.js`：挑战流程、轮次推进、中断恢复和提交。
- `public/js/tray-diff.js`：计算快照间的客观变化。
- `public/js/choice-profile.js`：镜鉴确认、选择图谱和原型展示。

现有 `public/app.js` 继续提供沙具目录和编辑器能力，并在主导航中增加与「沙盘报告」并列的「每日热题」入口。新增模块通过小型 bridge 调用沙盘快照、渲染和保存接口，避免把完整挑战状态重新塞回主文件。`public/js/community.js` 扩展挑战作品字段、公开原型展示和可选标签匹配，但不复制发布、互动或好友申请实现。

### 9.3 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/challenges/daily` | 获取当日挑战或内置降级挑战 |
| `POST` | `/api/challenge-runs` | 创建一局并保存初始快照 |
| `PATCH` | `/api/challenge-runs/:id/rounds/:roundId` | 保存一轮结果与操作摘要 |
| `POST` | `/api/challenge-runs/:id/reflection` | 生成结构化选择镜鉴 |
| `POST` | `/api/challenge-runs/:id/confirmations` | 保存玩家确认、否认或改写 |
| `GET` | `/api/choice-profile` | 获取当前用户的私人选择图谱和原型 |
| `PATCH` | `/api/choice-profile/archetypes/:id` | 更新单个原型的公开与匹配许可 |
| `DELETE` | `/api/choice-profile/records/:id` | 删除记录并重新计算原型 |

所有挑战记录均绑定当前登录用户。服务端不信任客户端提交的用户名、所有者 ID、原型或统计结论。

## 10. 数据模型

### 10.1 ChallengeRun

```json
{
  "id": "run-id",
  "ownerId": "zhihu-user-id",
  "challengeId": "2026-09-15-change-01",
  "status": "in_progress",
  "startedAt": 0,
  "completedAt": null,
  "initialSnapshot": [],
  "selfNarrative": "",
  "rounds": [],
  "reflection": null,
  "confirmations": []
}
```

### 10.2 RoundRecord

```json
{
  "roundId": "approach",
  "dimension": "change",
  "startedAt": 0,
  "completedAt": 0,
  "before": [],
  "after": [],
  "actions": [],
  "diff": {
    "added": [],
    "removed": [],
    "moved": [],
    "resized": [],
    "rotated": [],
    "firstMeaningfulAction": null
  },
  "skipped": false
}
```

坐标、缩放、旋转、沙具 ID、动作数量和快照大小沿用并收紧现有社区沙盘校验边界。服务端重算关键差异，不直接采用客户端提交的推断字段。

### 10.3 Confirmation

```json
{
  "observationId": "observation-id",
  "dimension": "boundary",
  "result": "confirmed",
  "userMeaning": "我确实会先确认自己有退路。",
  "createdAt": 0
}
```

`result` 只允许 `confirmed`、`situational`、`rejected` 和 `rewritten`。

## 11. AI 输入与输出边界

AI 仅接收：

- 经校验的挑战主题与轮次文本；
- 沙盘快照的结构化差异；
- 玩家主动填写的本局自述；
- 与本次观察直接相关的已确认或已否认模式。

AI 不接收不必要的知乎用户资料、好友关系、社区评论或其他玩家的私人数据。

观察输出使用结构化 JSON：

```json
{
  "observations": [
    {
      "id": "obs-1",
      "dimension": "boundary",
      "evidence": ["round-1:first-move-fence", "round-4:added-buffer"],
      "fact": "两次情境中都先调整了边界元素。",
      "possibilities": ["先确认安全条件再接近变化", "偏好层次清晰的构图"],
      "question": "哪一种更接近你当时的想法？"
    }
  ]
}
```

服务端验证 `evidence` 引用真实存在的动作，并限制观察数量、维度、文本长度和措辞。校验失败时不向玩家展示推测，只返回规则化事实摘要。

## 12. 状态、异常与降级

- **知乎热榜不可用：** 返回当前日期的内置挑战。
- **AI 命题生成失败：** 使用相同主题的人工模板；仍按日期缓存。
- **AI 镜鉴失败：** 展示快照对比、操作回放和规则生成的客观事实。
- **网络中断：** 浏览器暂存当前轮；恢复后用运行 ID 续传，服务端按轮次幂等更新。
- **中途退出：** 保留 `in_progress` 状态，下次登录可继续或主动放弃。
- **不适或跳过：** 标记 `skipped`，不参与心理统计，也不惩罚玩家。
- **非法客户端数据：** 拒绝该轮提交并保留上一份有效快照。
- **证据不足：** 不生成选择原型，并说明还需要更多经确认的记录。

## 13. 隐私与用户控制

- 选择图谱默认仅本人可见。
- 未经确认的观察仅保留在对应局内，不进入跨局画像。
- 玩家能删除单局记录、镜鉴卡或全部选择图谱。
- 删除单局记录后立即重算原型和统计。
- 分享前明确预览公开字段，默认排除自述和完整 AI 分析。
- 原型支持逐个公开或隐藏、允许或禁止参与匹配，也能整体关闭和清空，不影响继续参与挑战。
- 好友匹配默认不使用原型；每次启用时只允许选择当前已公开的原型。
- 所有相关页面持续展示“非心理诊断、不能替代专业帮助”的说明。

## 14. 测试策略

### 14.1 单元测试

- 热榜风险过滤与主题抽取；
- 挑战 JSON 白名单校验；
- 沙盘快照差异和首个有效操作计算；
- 确认状态对长期统计的影响；
- 原型证据阈值、跨情境要求和删除后重算；
- 高风险措辞和诊断式输出拦截。

### 14.2 API 测试

- 相同北京时间日期返回相同挑战；
- 热榜、AI 和缓存异常分别正确降级；
- 未登录用户不能创建、读取或修改私人挑战记录；
- 用户不能访问或覆盖他人的运行记录；
- 重复提交同一轮保持幂等；
- 非法快照、越界坐标和伪造证据被拒绝；
- 未确认观察不进入选择图谱；
- 删除记录后原型重新计算。
- 未公开原型不会出现在作品、用户或匹配接口中；
- 关闭标签匹配后，匹配分数与原有结构匹配保持一致；
- 启用标签匹配时，仅本次勾选且双方公开的原型参与计算。

### 14.3 前端测试

- 初始快照提交后不可被后续编辑覆盖；
- 轮次限制、跳过、中断恢复和完成状态正确；
- 初始/最终对照和关键变化回放正确；
- 确认、否认、限定和改写均写入正确状态；
- 分享预览不包含私人字段；
- 主页「每日热题」与「沙盘报告」并列存在，原自由创作入口和流程保持可用；
- 挑战作品可以通过现有发布页面进入社区，并继续使用评论、收藏、共鸣匹配和好友申请；
- 其他玩家只能看到作者主动公开的原型，作者可以随时撤回；
- 现有探索、报告和社区流程不回归。

## 15. MVP 验收标准

- 登录用户能从当日知乎热榜获得一个通过安全校验的每日挑战。
- 无合适热榜或 AI 失败时，用户无感切换到《为未知留一个位置》。
- 用户能建立初始沙盘，完成变化、取舍、关系及一次反向重演。
- 系统能保存并回放每轮关键变化。
- 镜鉴至少包含一条有真实动作证据的观察和一个替代解释。
- 玩家可以确认、限定、否认或改写观察。
- 只有符合确认规则的记录进入私人选择图谱。
- 达到证据阈值时出现可变化的选择原型；未达到时不强行生成。
- 玩家可以主动分享镜鉴卡，私人自述和完整图谱默认不公开。
- 首页同时保留原自由沙盘玩法，并提供位于「沙盘报告」旁的「每日热题」入口。
- 每日热题结束后可发布挑战沙盘，并复用现有社区和好友匹配流程。
- 玩家可以逐个选择公开原型；其他用户只看到已公开部分。
- 好友匹配可以由玩家选择是否纳入公开原型，不启用时沿用原匹配结果。
- 现有自动测试通过，并新增挑战、隐私、降级和原型测试。

## 16. 三分钟演示脚本

1. **0:00—0:25：** 登录后看到由知乎热点抽象出的今日命题。
2. **0:25—0:55：** 快速完成预置的初始沙盘，说明每件沙具由玩家自己定义。
3. **0:55—1:40：** 完成一个变化情境和一个反向重演，展示操作被实时记录。
4. **1:40—2:15：** 播放两次关键变化，展示“事实 → 两种可能 → 玩家确认”。
5. **2:15—2:40：** 打开长期选择图谱，展示原型如何由多局已确认记录产生并随时间变化。
6. **2:40—3:00：** 分享镜鉴卡到社区，查看同一命题下其他玩家提供的替代选择。

演示结语：

> 传统测试让你选一个答案，沙游心语让你亲手改变一个世界。我们不替你定义自己，只把你一次次作出选择的过程还给你看。

## 17. 实施顺序建议

1. 沙盘快照、动作记录和差异计算；
2. 内置挑战与单局状态机；
3. 镜像试炼界面、重演和中断恢复；
4. 结构化镜鉴、玩家确认与规则降级；
5. 私人选择图谱、原型计算和逐个公开控制；
6. 知乎热榜主题抽取、安全过滤和每日缓存；
7. 挑战作品复用社区发布流程，并展示自选公开原型；
8. 将公开原型作为默认关闭的可选好友匹配维度；
9. 完整回归测试和演示彩排。

该顺序优先验证“沙盘变化是否真的能产生有价值的自我观察”，再接入每日内容和社区扩散能力。
